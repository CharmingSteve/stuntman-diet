Import historical records

          
Upload multiple supported JSON files (combined maximum 5 MB), including overlapping exports and 18+ months of records. Preview and review before anything is committed.

          
Canonical imports send only structured fields and source identities. Browser exports send assistant text from the current branch for table extraction; user messages and unrelated metadata are stripped before upload. Original files and full transcripts are not retained as import sources. Derived records and source provenance are retained. Raw HTML, browser history databases, and arbitrary browser/chat formats are not supported.

          

            Supported formats, conversion help, and canonical example
            
ChatGPT exports and normalized text conversations: table-only extraction

            
Choose the browser-export format for a ChatGPT conversation object or array with id, mapping, and current_node. Only the active/current branch is followed, not alternate regenerated replies. Also supported: a text conversation object (or array) with id or conversation_id and messages containing id, role: "assistant", timestamp (ISO with offset) or create_time (epoch seconds), and content (a string or an object with a parts array of strings).

            
Only the latest supported two-column daily food table per inferred day is extracted. Dates come from the table message timestamp in your profile timezone, not dates guessed from prose. Every extracted row needs review. Free-text-only meals, health metrics, burn, and corrections are not extracted; the import may be incomplete. Verify the assigned day, timezone, final table, and source-versus-ledger totals. A reviewed day may differ from the source message day; the original timestamp and source identity are preserved. A total mismatch downgrades completeness to partial.

            
For browser chats without those tables, convert original evidence to canonical meal, burn, metric, summary, and correction records below for full fidelity. Keep stable source/message IDs, original timestamps with offsets, explicit corrections, and observed summary totals. Do not turn both cumulative tables and their component meals into additional intake.

            
Canonical JSON: full-fidelity structured records

            
Each file is an object with a stable conversation_id and messages array. Each message needs a stable id, timestamp (ISO 8601 with Z or an explicit offset), optional IANA timezone, and kind. Keep source IDs unchanged across reimports. Summary totals reconcile meals; they are not extra meals.
